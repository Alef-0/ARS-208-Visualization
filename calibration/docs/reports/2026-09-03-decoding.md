# Calibration third: OpenCV decoding and layout refactor

All 3,552 saved images were evaluated using OpenCV 5.0.0. The recording, journals and intrinsic coefficients were preserved. The full comparison uses the final tracker; alpha sensitivity uses every 25th image (143 images).

The linked detailed outputs require the original local `calibration_third_analysis`
folder; generated evidence is not included in the repository.

A frame/code pair counts one distinct journal index in one camera image, regardless of how many preprocessing variants/bands found it. These counts measure optical coverage, not decoding accuracy against independently labelled pixels. Checksum-valid reads are matched to a unique display journal entry and rejected if generated after camera receipt. Reading more codes often reveals retained or blended generations; it does not establish which marker was physically current.

Applying the viewer's selection rules to the complete combined pass leaves only **91 frames eligible for provisional offset statistics**. There are 1,081 frames without a single candidate because generations conflict, and another 2,380 provisional candidates are excluded by overlap or display-timing checks. None has a verified current underline, because this recording used the old borders. The complete counts are in [prediction eligibility](../../../recordings/calibration_third_analysis/final/prediction_eligibility.json).

## Contrast and alpha

Whole-frame binary thresholding recovered no journal-matched codes. Local binary retries added no codes beyond grayscale + CLAHE + learned bands in the 143-image sensitivity sample, across all five alphas. Local contrast is on by default and binary retry is off.

OpenCV already performs thresholding internally when decoding barcodes; applying a hard threshold beforehand can remove useful intensity information. [OpenCV implementation guide](https://github.com/opencv/opencv/blob/4.x/doc/tutorials/others/barcode_detect_and_decode.markdown).

| Undistortion alpha | Frame/code pairs, 143 images | Conflicting-panel frames | Frame/code pairs, final 48 sampled images |
|---|---:|---:|---:|
| 0 | 567 | 16 | 192 |
| 0.25 | 562 | 26 | 195 |
| 0.5 | 324 | 0 | 106 |
| 0.75 | 583 | 31 | 199 |
| 1 | 416 | 0 | 149 |

Across the full recording, original and alpha-0 images had the same newest decoded index in 2,889 frames. The original found a newer index in 504; alpha 0 found a newer index in 159. Those are optical comparisons, not verified current-marker decisions.

Alpha 0.75 gave the most sampled code coverage, with more conflicting-panel frames than alpha 0. Alpha 0 remains the initial setting; all five values are selectable. Original pixels are always decoded, with corrected pixels added when comparison is enabled. Alpha is OpenCV undistortion crop/field of view, not opacity or interpolation between timestamps. [OpenCV calibration reference](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html).

The first 95 sampled frames and final 48 are reported separately. This is a chronological sensitivity check within one recording, not independent validation across cameras or manually labelled exposure times. The provided intrinsic file has no image_size, so its applicability to these 1920×1080 camera images remains an assumption.

## General location tracking

Locations are learned from journal-matched detections per corner and image variant. The implementation stores up to 24 recent geometric observations, rejects oversized merged boxes, and decodes three interior bands. A narrower valid box can replace an initial merged box. Tracking resets on seeking or corroborated movement in multiple panels; unsupported regions expire after 60 analyzed frames. No screen coordinates from this recording are hardcoded, and no previous timestamp is reused when a region stops decoding.

| Image variant | Tracker movement resets in full pass | Learned corners |
|---|---:|---|
| original | 0 | 1, 3, 4 |
| alpha_0 | 0 | 1, 2, 3, 4 |

Corner numbers above are clockwise: 1 top-left, 2 top-right, 3 bottom-right, 4 bottom-left. The original view can fail to discover one corner while undistortion reveals it; regions are learned independently for each geometry. Location spread and median quadrilaterals are retained in the JSON summary.

## Code and display changes

- Removed the ZBar decoder and custom EAN bit/scanline parser. OpenCV handles discovery and regional decoding. Historical cached ZBar evidence can still be read by the old report-analysis script without loading a decoder.
- Removed the redundant decoder selector and unused drawing wrapper. Added local contrast, binary retry and undistortion-alpha controls to the viewer, with matching overlay transforms and cache resets.
- Replaced the current-marker border with a white underline below the time. It is outside barcode decoding regions and is erased when the next marker becomes current.
- Increased horizontal/vertical panel gaps from 32/32 to 48/64 pixels at 1920×1080, preserving eight-pixel barcode modules. The single persistent canvas and one flip per presentation remain.
- Old outline recordings are provisional in the viewer; borders no longer decide which timestamp is current there. The stricter CLI preserves legacy journal compatibility and decodes barcode bands separately from indicator pixels.
- Different generations in one panel, contradictions between image variants, multiple current indicators, unexpected blank-panel content and suspect/unknown replacement timing cannot produce a trusted offset. Direct and one-period inference checks remain covered by tests.

## Validation and use

72 focused tests passed, covering display history, underlines, legacy outlines, perspective registration, blank frames, learned-region movement, conflicts, alpha coordinate round trips, timing exclusions and existing workflow. The historical audit script also ran on a small sample of the first and second recordings. Recorded-image inspection exercised the viewer data path and verified finite overlay coordinates without opening a window. No build, commit or live UI test was performed.

Run the viewer from the repository:

```bash
python3 visualize_calibration_recording.py recordings/calibration_third
```

Reproduce the full recording comparison:

```bash
python3 -m calibration.analysis.evaluate_decoding recordings/calibration_third \
  --intrinsics "/media/alef/Everything/SEGCOM/Segcom Sincronização GERAL/Extrinsic/intrinsic_coefficients.json" \
  --step 1 --alphas 0 --output-dir recordings/calibration_third_analysis/recheck
```

For sensitivity, use `--step 25 --alphas 0 .25 .5 .75 1 --binary` and a separate output directory.

Outputs: [full summary](../../../recordings/calibration_third_analysis/final/summary.json), [full observations](../../../recordings/calibration_third_analysis/final/observations.jsonl), [alpha sensitivity](../../../recordings/calibration_third_analysis/sensitivity_v2/summary.json). The full summary includes input and source hashes; observations include image hashes, locations, preprocessing and rejections.

The new underline and spacing require user inspection on the actual display and a new recording for optical validation. This recording predates that layout. No new camera latency correction is recommended from these provisional readings.
